# 设计讨论摘要（claude.ai 对话 → 本项目）

这是项目启动前在 claude.ai 里的全部讨论的摘要，按时间顺序，记录每一步的结论和理由。
完整原始对话如有导出，放在 `docs/chat-transcript.md`（可选）。

---

## 1. 起点：让 AI 模仿我的聊天风格

三条技术路线，从简单到复杂：
- **A. 风格指南 + 示例（prompt）**：低成本，先跑起来
- **B. 检索增强（RAG）**：数据量大时动态检索「过去在类似情况下怎么回」
- **C. 微调（LoRA）**：最像，但容易学歪（编造经历）

数据处理决定上限：导出 → 清洗（非文本替换为占位符，占位符本身是风格）→ 按时间间隔切会话 → **保留连发结构**（一句话拆三条是关键风格特征）→ 脱敏 → 按对象关系打标签（对不同人说话差别极大，混在一起得到「平均的你」）。

风格提炼分定量（长度、拆条、标点、语气词、表情包、中英夹杂）与定性（怎么开玩笑、怎么不同意、怎么安慰）。AI 总结的风格常偏「漂亮」，需人工审核保留具体细节。

评估：盲测（真实 vs 生成，熟人分辨率接近 50% 即成功）、分布对比、「这句不像我」错误日志回灌。

## 2. LoRA 微调的效果与成本估算

- 7B LoRA（bf16）约 18–22GB 显存，4090 可跑；14B 需 QLoRA 或 A100。
- 1 万段对话训 3 轮：7B 约 2 小时（$1–2）；14B QLoRA 约 4–5 小时。实际需 5–15 次迭代，总 GPU 费 $30–150。
- 时间成本是大头：数据清洗 15–30h，环境 3–8h，迭代 10–20h。
- 效果：表面风格 ★★★★★，口头禅 ★★★★（易过头），分对象语气 ★★★，幽默 ★★，理解上下文 ★★，不编造事实 ★。
- 数据量：<2000 条收益有限；1–5 万条明显；>10 万边际递减。
- 常见坑：过拟合复读、事实幻觉、风格平均化、小模型能力下降。折中：大模型理解 + 小模型改写口吻。

## 3. Skill / RAG 做法

- **Skill 做法**：SKILL.md + style/ + examples/ + corpus/ + search.py（纯本地 char n-gram + BM25，claude.ai 代码环境不能联网所以不用向量模型）。零部署，手机端可用，缺点是只能字面相似。
- **自建 RAG**：检索单元是「语境→回复」对（向量化的是对方最后 1–2 句）；中文 embedding（bge-m3 类）本地跑；混合检索（向量+关键词）→ 按关系过滤、近期加权、MMR 去重 → prompt 拼装顺序：核心规则→关系风格→示例（标明「模仿节奏不照抄内容」）→当前对话→格式要求 → 代码后处理检查硬规则，不合格重写。
- 效果与微调对比：表面略逊（Claude 底色偶尔透出：太得体、太照顾情绪），长对话明显更强。主要风险：把示例里的真实事件搬进新回复 → 脱敏 + 明确规则。
- 推荐路径：先 Skill，用一两周记错误日志，再升级 RAG，再考虑微调。

## 4. 两个 app 想法的可行性

**想法 1：导入聊天记录，bot 模仿对方。** 技术难点：数据单向（只有 ta 对你说话的样子，事实严重不足 → 需用户补充事实）；编造的后果更严重。架构：导入解析（指定目标说话人）→ 人格构建（自动抽取 + 用户逐条确认）→ 事实层（source/confidence/time_scope/evidence；用户添加优先于自动抽取；时间范围）→ 「不知道」时含糊/反问并提示补充 → 记忆层保证前后一致。
最大问题：被模仿者未同意；前任/暗恋场景风险最高；他人聊天内容是其个人信息。
监管：中国《人工智能拟人化互动服务管理暂行办法》2026-07-15 施行（安全评估、算法备案、未成年人/老年人、个人信息）；加州 SB 243 2026-01-01 生效（披露、危机处理、年报、私人诉权，责任在 app 开发者而非模型方）；大模型使用政策对模拟真人也有限制。
缓解：定位为纪念/回忆，持续标明 AI，时长提醒，心理支持资源，不允许导出，一键删除，本地处理。

**想法 2：模仿自己的自动回复。** 最大障碍是平台接入：微信个人号无官方 API、第三方 hook 封号风险高；企业微信/Telegram/邮件可以；iMessage 勉强；WhatsApp/Discord 个人号不行。三种模式：回复建议（输入法/截图，最可行）、半自动审批队列、全自动（仅有 API 的平台 + 严格「不自动回」规则：钱、承诺、约时间、敏感话题）。反馈闭环（用户修改 = 高质量数据）最有价值；接日历避免乱答应。全自动被发现会伤害信任，默认建议模式。

两者共用核心引擎：人格 = 风格层 + 事实层 + 记忆层；区别只是目标人物是对方还是自己。

## 5. 本地部署 vs 云端 API

- 结论：开发验证用云端 API；处理原始聊天记录的环节放本地；混合架构（本地解析/脱敏/向量化/检索 + 云端生成）。
- 个人工具每天 50 次、每次 5K token，月费几美元到十几美元；买高端显卡几年才回本，本地部署的理由是隐私不是省钱。
- 配置档位：入门 8–12GB 显存/16GB Mac → 7–8B 量化；**推荐 24GB 显卡或 32–48GB Mac → 27B 量化**（Qwen3.6-27B Q4 约 18GB，~25 tok/s）；多人服务 A100/H100 + vLLM。
- 要给上下文留显存（RAG prompt 4–8K）；向量模型两三 GB 可跑 CPU；个人用 Ollama/LM Studio，上线用 vLLM。
- 本地小模型对「严格遵守风格规则」明显弱于大模型，需盲测对比。
- 面向中国大陆：海外 API 不可直接用；自部署开源模型不免除备案义务。

## 6. LLM 模仿风格的原理

模型只做「接下一个字」，模仿风格 = 让条件概率分布偏向「你会说的字」。预训练读过海量文本，内部已有「风格空间」，模仿是在其中定位。三种方法：规则（抽象描述，像给演员人物小传）、示例/RAG（上下文学习，归纳头复制模式，也因此会抄内容）、微调（改参数，学到细微习惯但风格与内容缠在一起 → 编造经历）。「AI 味」来自助手训练形成的引力中心，需用禁止项和后处理对抗。表面风格（每句都出现）易学；深层（幽默、角度、沉默）难，因为模型模仿的是文字的统计规律而非写下文字的人。

## 7. 权重空间编程（MIT 博客 2026-11-02）

结论：**不适合本项目**。它擅长修集中的毛病（减掉一个方向），不擅长加新能力；风格信息在聊天记录里不在权重里（最终还是要用数据 → LoRA 更便宜成熟）；最大语言模型实验仅 0.8B；成本与隐私更差；工具未公开。
可借鉴：激活引导（steering vector）——用「你的真实回复 vs 助手腔回复」两组对照算出方向，生成时加上，可压制助手腔（粗粒度），本地 7–8B 可试。

## 8. 「如果是ta，会怎么做」：人格模拟

- 严格说不是「世界模型」（世界模型预测环境动态）；是人类行为模拟 / 生成式智能体 / 数字孪生 / 心智理论。可视为世界模型中「人」的组件；加上「选择之后会发生什么」就是围绕这个人的小世界模型。
- 证据：斯坦福《Generative Agent Simulations of 1,000 People》——两小时访谈全文放进 prompt，GSS 问卷复现达真人两周自复现的 85%（原始 68.85% vs 81.25%）；基于访谈远好于人口标签（高 14–15 点）。摘要不如全文。
- 与风格模仿的区别：怎么说 vs 怎么选；聊天记录对后者价值有限，需经历、关键抉择及理由、价值观。
- 设计：AI 访谈采集 → 知识分层（原始叙事 / 决策案例库：情境→选项→选择→理由→结果→反思 / 价值观画像 / 时间线）→ 推理（检索相似抉择 + 第一人称推理 + 输出概率分布 + 多次采样）→ 回测。
- 局限：人本身不一致（真人两周自复现仅约八成）；心路历程是事后重构；AI 把人模拟得更理性善良；研究验证的是问卷不是人生大事。
- 用途：模拟过去/未来的自己、塑造小说角色、纪念、社科研究；慎用于揣测未同意的真人。

## 9. 结构化方法（不只 prompt + LLM）

效用/离散选择模型（权重透明）、联合分析（主动二选一提问反推权重）、风险与时间偏好参数、逆向推理目标（贝叶斯心智理论/IRL）、BDI 模型、案例推理、因果图、用选择数据微调（Centaur, Nature 2025，预测人类一般选择）。
推荐**混合架构**：大模型做翻译（叙事↔结构），结构化模型做计算；档案含价值权重（带置信度与证据链接）、风险参数、决策案例、信念、原始叙事；预测时双路径（效用模型 vs 案例检索+第一人称），一致→高置信，不一致→标记分歧；主动提问（挑最不确定的权重出题）；贝叶斯更新；回测校准。结构化部分能牵制大模型「把人想得太理性太善良」。

## 10. 画像/侧写的生成方式

建档阶段 = 大模型按框架整理（离线）；使用阶段 = RAG 检索原文证据。画像是概括，原文是证据，缺一不可。
流程：切块 → 逐块抽取（固定框架、必须附原文、标明行为/自述/他评）→ 汇总合并（统计支持/矛盾证据；一次出现是线索，反复出现才是特质）→ 综合成像 → 人工审核 → 版本管理。
框架：McAdams 三层人格（特质 / 动机与适应方式 / 人生叙事）+ 矛盾与张力 + 不确定与空白。
两种形态：结构化 JSON（给机器）+ 可读侧写报告（给人，每个判断可点开出处）。
注意：防框架绑架（证据不足写「不确定」而非硬套 MBTI）、区分说的与做的、防美化、本人审核是证据不是裁判。

## 12. 分层网状图谱（2026-11，参考 Graphiti）

问题：早期图谱是以 ta 为中心的星形，只有「ta → 观察/事件/人物」；reflect 按维度各自进行，无法产生跨维度联系；特质没有记录推导过程；矛盾只是一个 tag。

改为五层：L0 原文（Episode）→ L1 实体与实体之间的事实边 → L2 观察 → L3 特质 → L4 主题。
- 借鉴 Graphiti：episodic/entity/community 三层子图与双向追溯（MENTIONS/SUPPORTS）；事实即实体间的边；实体消解（候选 + LLM 判定，保留别名）；同一对实体间的事实去重；按类型对约束允许的关系（edge_type_map）；`expired_at` 补齐双时间轴；标签传播做社区；检索加 BFS 图邻域并与 BM25 做 RRF 融合。
- 不照搬：Graphiti 用新事实让旧边失效（覆盖矛盾），与「允许矛盾」冲突。这里区分 `contradiction`（同期，两边都有效，连 CONTRADICTS 边）与 `change`（跨期，旧的设 valid_to，连 CHANGED_TO 边）。不引入 Neo4j/向量依赖。
- 置信度改为代码计算（scoring.py），因为模型自报的置信度普遍偏高（0.8–0.98）。
- 特质含敏感（J）依据时整条特质标 sensitive，不进聊天和决策。
