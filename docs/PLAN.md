# 如是 · 项目计划

> 「如果是ta的话，也一定会这么做的。」

## 一、定位与原则

**一句话定位：** 一个带时间线的人格记忆图谱，加上两个引擎（说话引擎、决策引擎），让用户可以和「记忆中的某个人」对话，也可以问「如果是ta，会怎么做」。

1. 证据优先：每条结论可追溯到原始材料；无证据的判断标记为推测。
2. 时间是一等公民：每条信息带「什么时候成立」；问 ta 会怎么做时先问「哪个时期的 ta」。
3. 允许矛盾：矛盾是人格的一部分，保留并标注。
4. 诚实的不确定性：输出概率和依据，而不是断言。
5. 纪念而非替代。

## 二、总体架构

```
输入层    聊天记录 │ 用户口述/访谈 │ 对事件的看法 │ 日记/文章 │ 他人回忆
摄入层    解析 → 切分 → 脱敏 → 时间对齐 → 逐块抽取 → 冲突/合并
记忆层    原始语料库（向量+关键词索引）
          时态知识图谱（实体、事件、观点、价值、关系，带有效期）
          决策案例库
          人格画像（分层，带证据和置信度，定期重新综合）
引擎层    风格引擎（怎么说） │ 人格/决策引擎（想什么、怎么选）
应用层    聊天 bot │ 「如果是ta」问答 │ 后台画像/图谱浏览 │ 多人格沙盒
```

记忆层是核心资产；引擎和应用都可以换。

## 三、记忆层：时态知识图谱

- 节点：Person / Event / Decision / View / Value / Trait / Relationship / Utterance / Source
- 边带双时间轴：`valid_from/valid_to`（人生中何时成立）、`recorded_at`（何时得知）。冲突时不删旧边，设 `valid_to`。
- `evidence_type`：behavior（实际做了）> self_report（自述）> other_report（他人评价）。
- 摄入流程：解析切分 → 时间对齐（标不出的标「未知」，不让模型猜）→ 逐块抽取（必须附原文引用）→ 冲突与合并 → 定期反思（跨观察综合高层结论，源自斯坦福生成式智能体的 reflection）→ 人工审核队列。
- 增量生长：用户随时补充，走同一流程，标记来源；后台显示证据缺口。

## 四、风格引擎（怎么说）

风格卡 = 消息长度与拆条、标点、语气词与口头禅、表情包时机、对不同关系的差异、开场/结束；按时期分版本；对话时检索相似语境的真实原话做示例；后处理用代码检查硬性规则；人格层决定「说什么」，风格层决定「怎么说」。

## 五、人格引擎（想什么、怎么选）

### 5.1 画像维度（抽屉清单，证据不足就空着）
A 身份与背景 · B 人生时间线 · C 价值观与优先级 · D 世界观与立场（分议题记录立场和强度，不贴左右标签）· E 道德判断 · F 人际关系模式（依恋方式、冲突处理、信任、边界、交友模式、对背叛和原谅的态度）· G 感情观 · H 工作、金钱与风险 · I 兴趣与审美 · J 童年与形成性经历（敏感：单独存储、默认不进聊天、只记录明确陈述，不允许模型推断创伤）· K 压力与情绪 · L 认知与决策风格 · M 自我认知与人生叙事 · N 恐惧与渴望 · O 幽默与表达 · P 矛盾与两难登记簿 · Q 变化轨迹

### 5.2 决策引擎：「如果是ta，会怎么做」
1. 定位时期 → 2. 解析情境（人、关系、选项、触及的价值与恐惧）→ 3. 检索（相似决策案例、价值/观点、关系、矛盾）→ 4. 双路推理：结构化路径（价值权重×影响→概率）+ 叙事路径（第一人称带记忆推理）→ 5. 合成：概率、依据、分歧点、ta 可能会说的话、不确定性 → 6. 用户反馈回流为证据。
校准：藏起已知历史决策做回测。

## 六、信息怎么整合进 LLM

分层记忆（RAG 只是其中一层）：
1. 常驻核心人格卡（1–2K token）
2. 按需混合检索（向量 + 关键词 + 图谱邻域，按关系/时期过滤）
3. 模型主动查询工具 `search_memory`

参考：mem0（抽取 + ADD/UPDATE/DELETE/NOOP + 向量/图；人格记忆不应 DELETE）、Letta/MemGPT（分页式核心/归档记忆）、Zep Graphiti（时态图谱，失效而不删除——最贴合）、斯坦福生成式智能体（记忆流打分 + 反思；1000 人版本直接把访谈全文放进 prompt，85% 复现率）、Character.AI / SillyTavern 角色卡 + 世界书 / ChatHaruhi（检索原台词）、Character-LLM（经历微调）、HereAfter/StoryFile 等纪念类产品。

## 七、多人格沙盒成故事

可行，属于「涌现式叙事 / 自底向上故事生成」（StoryBox, AAAI 2026；EvoSpark 2026；斯坦福小镇情人节派对实验）。
架构：作者输入世界设定与边界事件 → 沙盒（每角色 = 人格图谱 + 风格卡 + 记忆；感知→检索→计划→行动→反思）→ 导演层（监测张力、注入扰动、作者介入）→ 叙事层（事件筛选→结构化→成文）。
难点：容易「什么都不发生」（需异常因子/导演层）、长时程一致性、成本（5 角色×30 天×20 时刻≈3000–5000 次调用）、事件到小说的距离、真实人物入小说的伦理。
更实际的形态：作者的推演沙盒——设定情境，跑多次，把有意思的分支拿去自己写。**沙盒与人格单向隔离，小说不回写人格。**

## 八、实施路线

- 阶段 0（1–2 周）数据与原则 ✅
- 阶段 1（3–4 周）单人格 MVP：聊天记录 + 口述 → 库 → 人格卡 + RAG 聊天 ✅
- 阶段 2（4–6 周）时态图谱与画像：有效期、逐块抽取、冲突、反思、后台画像、审核队列 ✅（CLI + 静态 viewer）
- 阶段 3（4–6 周）决策引擎：案例库、双路推理、概率输出、回测 ✅
- 阶段 4（持续）增量生长与评估：补充入口、缺口提示、盲测、回测 ✅
- 阶段 5（探索）多人格沙盒：先两角色一场景一天 ✅（最小雏形）

## 九、技术选型

生成模型用云端大模型（遵守复杂规则的能力最重要）；抽取可用便宜模型；向量模型用中文友好的开源模型本地跑；图起步用 SQLite/PostgreSQL 自建，规模大了再上 Neo4j/Graphiti；记忆框架自建（人格记忆「不删除、留矛盾」的语义与通用框架不一致）；原始材料本地加密，发往云端的只有脱敏片段。

## 十、评估

风格：盲测分辨率、特征分布对比。画像：证据覆盖率、审核通过率、「惊讶但认同」比例。决策：回测准确率、与基线对比、事后评分。系统：token 消耗、检索命中率、记忆增长曲线。

## 十一、风险与边界

对用户：可能延长悲伤或造成依赖——时长提醒、「这是模拟」标识、支持资源。被模拟者：个人信息；家人分歧。监管：中国《人工智能拟人化互动服务管理暂行办法》（2026-07-15 施行，适用范围几乎就是本产品）；加州 SB 243（2026-01-01 生效，披露、危机处理、私人诉权，责任在应用开发者）。敏感维度默认后台可见。模型美化倾向：靠结构化路径和矛盾登记对抗，评估时专查「不讨喜但真实」的特质是否保留。
